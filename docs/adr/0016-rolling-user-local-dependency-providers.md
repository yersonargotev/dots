# Add closed rolling user-local dependency providers

High-release-cadence Agent CLIs make manifest-pinned versions and checksums create continuous Source of Truth churn. Mutable vendor installer scripts, arbitrary repositories, and package-manager fallbacks would weaken the reviewed User-Local Provider boundary. A missing Dependency still needs a reviewable Dependency Plan before any Managed Configuration or Provisioner mutation.

**Decision**: add a separately named `rolling_user_local` Install Manifest policy whose only field is an allowlisted recipe. A recipe owns its official metadata endpoint, stable-release filter, Supported Platform asset mapping, archive layout, executable path, and destination. Resolution happens only after normal command probes report the Dependency absent. It must produce a stable version, unique immutable artifact URL, and valid official SHA-256 digest before the action becomes installable. Resolution failure fails closed without falling back to scripts, package managers, or unverified downloads.

Codex is the tracer-bullet recipe. It reads stable release metadata from the official `openai/codex` GitHub repository, selects the official `codex-package-<target>.tar.gz` asset for macOS or Linux on amd64 or arm64, and consumes the digest attached to that release asset. Installation verifies the downloaded bytes, applies archive traversal and expansion limits, stages the versioned bundle under `~/.local/opt/codex/<version>`, and atomically replaces `~/.local/bin/codex`. The provider does not modify `PATH`; a required Dependency remains unresolved when the installed command is not visible to the current process.

Dependency plans, dry runs, and structured output expose the resolved recipe, version, artifact, URL, digest, platform, layout, command, and destination. A successful Dependency Installation receipt records the same release evidence plus installed path and timestamp. The receipt is audit evidence, not enforced desired state: a later command already present on `PATH` prevents lookup, update, or replacement.

**Consequences**: read-only plans may perform network resolution for an absent rolling Dependency. Tests must inject a controlled HTTP release server and never call live release services. Existing fixed `user_local` recipes and their version/checksum contract remain unchanged. Future rolling recipes require code review because the manifest cannot supply repositories, URLs, commands, checksums, or installer scripts.
