# Resolve fast-moving Agent CLIs with verified rolling providers

The Agent CLI Baseline will install missing Codex, Claude Code, OpenCode, Antigravity, and Copilot CLI capabilities through Rolling User-Local Providers. These closed, allowlisted providers resolve only the latest stable artifact from official metadata, require a published checksum or digest before installation, use the existing home-owned layout, and record the resolved release as Dependency Installation Metadata. A durable command already present on `PATH` satisfies its Dependency without network resolution, replacement, authentication, or update. Codex bundled inside `ChatGPT.app/Contents/Resources` is process-private rather than durable shell availability, so that match is skipped while probing the remaining `PATH` entries.

This decision partially supersedes ADR 0011 only for the separately named rolling category. Fixed User-Local Providers continue to declare versions and checksums in the Install Manifest. Rolling resolution moves that review boundary to allowlisted metadata sources, deterministic stable-release and platform-asset selection, fail-closed integrity verification, and a receipt that captures the version, URL, digest, platform, and installed path actually chosen. Dependency plans and dry runs may read official metadata to make that intent reviewable before mutation; missing or unverifiable metadata leaves a required Dependency unresolved and aborts installation before Managed Configuration changes.

**Considered Options**: Pinning all five tools in the Install Manifest was rejected because their daily release cadence would require continuous repository churn unrelated to dotfiles intent. A Homebrew/native-script hybrid was rejected because it cannot converge Linux machines without Homebrew uniformly, gives each tool a different installation and PATH boundary, and Antigravity has no official Homebrew package. Executing upstream `curl | sh` installers or resolving unverified latest artifacts was rejected because mutable remote code and inconsistent payload verification would bypass the reviewed provider boundary.

**Consequences**: Rolling resolution requires read-only network access when a selected command is absent, official-metadata adapters, deterministic stable/prerelease and platform filtering, safe archive handling, and structured preview fields for the resolved artifact. Vendor auto-update defaults remain outside dots' ownership after installation, so the receipt is audit evidence rather than an enforced current version. Providers do not mutate shell startup files; `~/.local/bin` remains an explicit PATH prerequisite.

**Codex tracer bullet**: The first closed recipe accepts only `rolling_user_local.recipe: codex`, reads stable release metadata from the official `openai/codex` repository, and selects the unique `codex-package-<target>.tar.gz` asset for macOS or Linux on amd64 or arm64. It requires the release asset's official SHA-256 digest before an action is installable. Installation verifies the downloaded bytes, enforces archive traversal and expansion limits, stages the versioned bundle under `~/.local/opt/codex/<version>`, atomically replaces `~/.local/bin/codex`, and records the resolved version, URL, artifact, digest, platform, installed path, provider, and timestamp.

**Claude Code provider**: The closed `rolling_user_local.recipe: claude` adapter reads only Anthropic's official `stable` channel and the selected release's versioned `manifest.json` under `downloads.claude.ai/claude-code-releases`. It selects `darwin-x64`, `darwin-arm64`, `linux-x64`, or `linux-arm64`, requires the platform's SHA-256 checksum, downloads the immutable raw `claude` executable directly, and never invokes Anthropic's installer script or a package manager. The verified binary is staged under `~/.local/opt/claude/<version>/claude`, exposed atomically at `~/.local/bin/claude`, and recorded through the same resolved receipt contract. dots leaves Claude Code's vendor auto-update behavior unchanged.

**GitHub Agent CLI recipes**: The closed `opencode`, `antigravity`, and `copilot` adapters reuse one GitHub release boundary with recipe-owned repository, asset matrix, archive layout, and installed command. They read only stable releases from `anomalyco/opencode`, `google-antigravity/antigravity-cli`, and `github/copilot-cli`, select the unique allowlisted macOS/Linux amd64/arm64 asset, require GitHub's published SHA-256 asset digest, and reject missing or duplicate matches. OpenCode extracts the root `opencode` executable from zip on macOS and tar.gz on Linux. Antigravity extracts the root `antigravity` executable from tar.gz and exposes it only as `agy`, without invoking the vendor installer. Copilot extracts the root `copilot` executable from tar.gz. All three preserve the shared archive path and expansion limits and record the same resolved receipt fields as Codex.
