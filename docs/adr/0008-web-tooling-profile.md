# Install frontend and browser agent tooling through an explicit web profile

The user wants frontend-focused skills and browser automation available on demand, not as part of the general agent or desktop setup. We add a dedicated `web` Profile/tag for the web workbench: selected design/React skills from `skills.sh`, Playwright CLI and its upstream skill, the Claude Chrome DevTools plugin, the Codex `chrome-devtools` MCP server, and the OpenCode MCP overlay. The existing `agents` profile stays focused on gentle-ai agent setup and broad engineering skills, while `desktop` stays focused on terminal/editor/GUI machine configuration and non-web desktop integrations.

This keeps profile names aligned with user intent. Choosing `--profile web` means “prepare this machine/session for frontend/browser work”. Choosing `--profile agents` no longer installs UI-review skills as incidental agent setup, and choosing `--profile desktop` no longer installs Chrome DevTools just because Chrome is a desktop application. The `workstation` profile intentionally does not include `web`; web tooling remains explicit opt-in so a full workstation bootstrap does not silently add browser/frontend agent capabilities.

**Considered Options**: Keeping `web-design-guidelines` under `agents` was rejected because it made web design review tooling part of the baseline agent setup. Keeping Chrome DevTools under `desktop` was rejected because the capability is browser/frontend-specific in practice, even though it requires desktop Chrome. Splitting this into separate `web-skills` and `browser-tools` profiles was rejected for now because it adds naming and selection complexity before there is a real workflow that needs only one half.

**Consequences**: Manifest profile selection now has a `web` tag. The web profile installs `frontend-design` from `anthropics/skills`, selected Vercel web skills from `vercel-labs/agent-skills`, `playwright-cli` from `microsoft/playwright-cli`, the Playwright CLI command, and Chrome DevTools integrations for Claude, Codex, and OpenCode. Documentation and repository manifest tests must treat Chrome DevTools and Playwright CLI as web-scoped from this point forward. This refines ADRs 0003, 0004, and 0005: their provisioning mechanics stay valid, but their profile placement moves from `desktop` to `web`. Implementation is tracked in [#145](https://github.com/yersonargotev/dots/issues/145).
