# Compare Herdr Auto Title with the task identity contract

Date: 2026-10-11. Tracking: [dots #543](https://github.com/yersonargotev/dots/issues/543), draft [PR #544](https://github.com/yersonargotev/dots/pull/544). This is research, not an installation or an architecture change. [ADR 0021](adr/0021-herdr-task-identity-plugin.md) records the previously accepted contract; the newly supplied existing product warrants reassessing implementation reuse before creating a repository.

## Conclusion

Herdr Auto Title is a substantial existing solution for contextual tab and pane naming. It can replace Tabby for that product and can supply the prototype's per-pane identity row and workspace topic without a new plugin. It does **not** implement the agreed stable Task Name contract as-is: its activity sources change independently of semantic task boundaries, its transcript extractor is Claude-specific, and its manual locks belong to resource IDs and visible labels rather than a native conversation and task generation.

That distinction is not a reason to automatically keep the new-plugin plan. There are two different product choices: accept contextual activity naming and reuse Auto Title, or preserve the explicit contract and evaluate a focused upstream extension against a dedicated component. Calling a substantial task-state extension “just config” would conceal the work; calling every useful existing feature irrelevant would duplicate it.

## Requirement matrix

| Codex and Claude both produce meaningful task names | Generic Herdr agent title and OSC terminal title work for any agent. Only Claude has an on-disk native transcript extractor. | Manual correction wins for the current task, then resets on the next task | Rename is detected between polls and locked until label is cleared/changes or resource disappears. | Protects manual resource naming, not task-limited correction. A different desired Activity does not unlock it. |
| Name and correction survive cold restart/resume of the same native conversation | Pane labels rely on Herdr's native persistence; persisted locks reload when resource ID and label still match. | Different conversation in the same pane inherits nothing | Lock record contains ID and label only. It does not compare the native conversation reference. | Missing strict isolation. A same-ID/same-label replacement can retain the correction. |
| Workspace topic/readability | Reports `$topic` for the active tab, without renaming the workspace. Token TTL is 60 seconds with 20-second unchanged refresh. | Available; topic is activity/context, not an authoritative stable task record. |
| Keep Tabby's current dynamic tab names while adding task identity | Auto Title always names tabs; its config exposes pane/workspace switches but no tab-renaming switch. | Conflicting ownership if both run unchanged. |
| Avoid external LLM requests | Resolver is deterministic; inspected runtime uses local socket/files, with no model or external HTTP client. | Satisfied for runtime. Claude's native generated title may originate from Claude itself; Auto Title does not make that request. |

## What actually names an agent

The resolution ladder puts Herdr `PaneInfo.title` first, then cleaned OSC terminal title, then session transcript, then foreground program, remote host, Git branch, cwd, and fallback. It fills Context and Activity independently. Pane labels preserve useful activity while reducing context repeated by the containing tab. It publishes manual pane labels, not separate `$task` pane metadata. This is a real fit for improving the Agent list, but the content is only as semantic as its source. [Resolution architecture](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/docs/architecture/title-resolution.md), [pane resolver](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/resolver/resolver.go).

`reads.Reader.topic` explicitly asks `pane.AgentSession.IDFor(claude.Agent)`. Claude reads the latest nonempty `ai-title` from its transcript, falling back to the first human-origin opening prompt; later ordinary prompts do not replace that opening. Both choices can diverge from the contract: a native title may evolve during a task, and the first prompt may remain after a distinct task begins. The format is acknowledged by the project as undocumented Claude internals. There is no equivalent Codex extractor in either inspected revision. [Routing](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/reads/reads.go), [Claude reader](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/claude/transcript.go).

The maintainer is open to additional agent support: a comment on the OMP issue says it is a natural direction and prefers one shared transcript switch. This is evidence of openness, not that Codex support or task-generation semantics already exist or are accepted. [Maintainer comment](https://github.com/kryptamine/herdr-auto-title/issues/125#issuecomment-5970817407).

## Manual persistence and identity boundaries

HEAD stores `locked_tabs` and `locked_panes` as ID-to-label maps. `retain` drops a lock only when its resource disappears or its label differs from the saved label; `Pass.Pane` skips a locked pane before applying a new desired title. There is no native conversation reference or task generation in the claims record. Thus two same-kind conversations using the same pane are not distinguished by this mechanism. This is a source-derived counterexample, not an observed live-session failure. Stable v0.13.1 has the same record and rule in `internal/state/manual.go`. [HEAD claims](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/labels/claims.go), [HEAD application of locks](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/labels/labels.go), [stable rules](https://github.com/kryptamine/herdr-auto-title/blob/9de68183c8a95141871cd3c0eff0c5be4e3fc6af/internal/state/manual.go).

The implementation writes locks through a temporary file and rename, but silently treats unreadable/corrupt state as an empty store and silently ignores save failures. Protection is therefore best-effort resource naming, not a fail-closed identity contract. The project also documents that the first start can overwrite preexisting manual pane names and that a rename while the plugin is stopped cannot safely be recovered from its current heuristic. Those are material migration/restoration limitations, not reasons to reject the whole product. [Persistence code](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/labels/claims.go), [load behavior](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/labels/labels.go), [manual protection design](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/docs/architecture/manual-rename-protection.md).

The default manual store is shared across simultaneously active named Herdr Sessions: `Config.ManualPath` is `ownPath("manual-names.json")`, with no socket-derived suffix. An explicit override is a literal path, not a session template. In contrast, the process-instance claim uses a hash of the socket path; that namespaces only instance markers. Thus independently running sessions load/write the same default lock file with potentially identical resource IDs. Cross-session interference and last-writer loss are source-derived risks relevant to this user's multi-session setup; no live concurrent-store failure was reproduced. A per-session configured file can avoid shared-file collisions only when each server reliably receives a distinct path, and it still does not add native conversation/task identity. [Path policy](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/app/paths.go), [configuration](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/app/config.go), [instance namespace](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/instance/instance.go), [entrypoint use](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/cmd/herdr-auto-title/main.go).

## Configuration, cost, and coexistence

The manifest builds from source using Go 1.24+, supports Linux/macOS/Windows, and sets Herdr 0.8.2 as its minimum. Dependencies are `uniseg` and `godotenv`. Runtime config lives in its own `herdr-auto-title/config.env`, resolved through XDG, `~/.config`, and platform config paths; it does not use Herdr's plugin config directory. A dots adoption would manage that portable config as a Managed Entry, keep mutable manual-name state outside the Installed Repository, and pin an exact reviewed revision. [Stable manifest](https://github.com/kryptamine/herdr-auto-title/blob/9de68183c8a95141871cd3c0eff0c5be4e3fc6af/herdr-plugin.toml), [module](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/go.mod), [path policy](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/app/paths.go).

It runs a long-lived per-session polling instance. Default interval is 500 ms, with one session snapshot per poll, cached process inspection refreshed after drawing or two seconds, local Git reads, incremental Claude transcript reads, and renames only when labels differ. Pane naming expands process observations to unclaimed panes. Poll interval is also a title-change-rate control, not a semantic debounce/new-task guarantee. Increasing it can reduce polling and visible churn without creating task stability. Disabling transcript reading avoids those local prompt-file reads but removes the strongest Claude fallback. No runtime external LLM call was found. [Poll design](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/docs/architecture/poll-loop.md), [process cache](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/reads/processes.go).

Pane names are not invariably full Context + Branch + Activity: `withoutAbove` removes repeated Context, Branch, and Agent while retaining Activity. The resolver test `TestAPaneKeepsItsActivityAndDropsTheSharedContext` yields a clean activity label. Other panes may retain their own differing context/branch or fall back to a directory. No config switch exposes an unconditional activity-only per-pane metadata token; only workspace `$topic` uses the topic-specific resolver. This is a qualification of the visual fit, not a claim that its pane labels are unusable. [Pane deduplication](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/resolver/resolver.go), [meaningful pane test](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/resolver/resolver_test.go), [topic resolver](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/resolver/topics.go).

Auto Title and Tabby both mutate `tab.rename` and recognize unexplained label changes as manual intent. Running both can cause either to lock the other's automatic label, not merely produce flicker. Auto Title exposes switches for pane naming and workspace topic publication, but no `TABS=false` or equivalent branch that suppresses tab naming. Prefer replacing one tab owner, or add an explicit upstream ownership switch, rather than enabling both unchanged. [Always-called `nameTab`](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/app/app.go), [config surface](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/app/config.go), [pinned Tabby contract](https://github.com/yersonargotev/tabby/blob/19031d668f0f8a79b58591db4ce8bc8f8846e329/README.md).

The Git metadata provider's `$tab_name` and `$git*` tokens are distinct from Auto Title's `$topic`, so they can coexist without token-key ownership conflicts. `$tab_name` would naturally show Auto Title's generated label if it becomes the sole tab owner. This is a contract-level inference; sandboxed integration is still required. [Pinned Git provider](https://github.com/yersonargotev/herdr-tab-git/blob/48fe5a66c17970a77919dc50a6ab3b6512bc7300/README.md), [Auto Title topic reports](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/app/topics.go).

## Validation and limits

Audited selected tests before execution: pure resolver/state fixtures, temporary transcript/store files, and stubbed Herdr clients. App tests use isolated temporary configuration and fake Herdr clients. Only the two pinned module dependencies were downloaded into task-scoped temporary `GOMODCACHE`/`GOCACHE`; the final tests ran with `GOPROXY=off GOTOOLCHAIN=local`. No plugin entrypoint, OS package manager, live probe, or installer script was run.

- HEAD: `go test -race ./internal/app ./internal/labels ./internal/resolver ./internal/claude ./internal/state` passed.
- Stable v0.13.1: `go test -race ./internal/app ./internal/resolver ./internal/claude ./internal/state` passed, including its manual-state tests.
- Existing tests cover locks surviving reload, changed labels releasing locks, manual names resisting a different desired label, clear-to-unlock, and Claude title/transcript behavior. None of these proves task-generation semantics that the record does not contain. [HEAD lock tests](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/labels/claims_test.go), [HEAD label tests](https://github.com/kryptamine/herdr-auto-title/blob/a5a2701d352dbab91ef3032a948e3aa7cb98f4e6/internal/labels/labels_test.go), [stable manual tests](https://github.com/kryptamine/herdr-auto-title/blob/9de68183c8a95141871cd3c0eff0c5be4e3fc6af/internal/state/manual_test.go).

No tests were added or changed. Both temporary source checkouts remained clean. End-to-end Herdr acceptance and actual Codex title availability were not exercised.

## Decision paths

1. **Reuse as-is, replacing Tabby:** suitable if the product becomes useful contextual activity titles, with manual locks released by clearing. Configure pane rows and optional `$topic` in dots. Explicitly relax stable-task boundaries, task-limited manual correction, strict conversation isolation, and equivalent Codex title guarantees. This is a simpler different contract, not equivalent fulfillment of ADR 0021.
2. **Extend upstream deliberately:** first discuss an explicit task mode/shared producer contract, native conversation/task-scoped persistence and correction, and tab-owner controls. Codex extraction alone does not solve semantic new tasks or override lifetimes. The needed changes touch resolver source semantics, persisted identity, lock policy, recovery, and actions; they may be cohesive if upstream wants that product, but they exceed configuration and a trivial adapter.
3. **Keep a dedicated narrow task component:** justified if the existing contract remains and upstream does not want those task-state semantics. Reuse Herdr's rendering/API, keep Tabby as the sole existing tab-label owner, and implement only the stable human Task Name and its conversation/task correction state. Do not recreate Auto Title's process/Git/terminal title machinery or workspace activity system.

Recommendation under the already selected contract: keep Tabby as the sole tab-label owner and keep any additional task-identity component narrow. Auto Title is not equivalent fulfillment as-is. A deliberate later decision to accept contextual activity naming would make reuse a strong alternative. Before implementation, an upstream task mode can be evaluated against the concrete ownership and acceptance requirements; its existence must not be assumed to make conversation/task state semantics a small patch. This comparison does not authorize creating a plugin or changing the installed selection.
